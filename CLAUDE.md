# CutePet

Online store for handmade pet clothing (La Paz, Bolivia). Angular 22 + Angular Material 3 + Supabase, SSR, pnpm.

- Business rules and scope: `docs/spec.md` (source of truth; if something is not there, ask).
- Architecture: `docs/ARCHITECTURE.md` (read it before creating files).
- For anything database-related use the `supabase` and `supabase-postgres-best-practices` skills (`.claude/skills/`) and the Supabase MCP. For Angular, the `angular-cli` MCP has the official v22 docs.

## Language

- **English:** code, identifiers, database names and enum values, comments, docs, commit messages.
- **Spanish (Bolivia):** everything the customer or admin sees: UI text, error messages, page titles, meta tags, URLs (`/catalogo`, `/pagar`), WhatsApp and Telegram message templates.
- Reply to the user in the language they write in.
- Never mix languages in identifiers (no `getPedidos()`). Use the glossary below.

## Commands

- `pnpm start` — dev server
- `pnpm check` — format + lint + tests + build. **Must pass before a task is done.**
- `pnpm db:types` — regenerate DB types from the local database (`supabase start`) after every migration
- Install packages only with `pnpm add`. Never npm or yarn.

## Commits

- Commit messages: one short line in English, imperative, under 72 characters (e.g. 'Add quick sale page'). A short body only when the reason is not obvious. No Co-Authored-By or other trailers.

## Generated files

- `src/app/core/supabase/database.types.ts` is generated by `pnpm db:types`. Never edit it by hand. It is excluded from ESLint and Prettier on purpose; lint rules do not apply to it.

## Dependency security

- pnpm blocks install scripts and enforces `trustPolicy: no-downgrade` (`pnpm-workspace.yaml`).
- Never add entries to `allowBuilds`, `trustPolicyExclude` or `minimumReleaseAgeExclude`, and never relax those settings. If an install fails because of them, stop and tell the user which package and why.
- Prefer packages that already exist in the project over adding new ones. Ask before adding a dependency.

## Rules against duplication and complexity (most important)

1. **Search before writing.** Before creating a component, service, helper or type, search `shared/`, `core/` and the feature for something similar. Reuse or extend it.
2. **Rule of three.** The second time something repeats, note it; the third time, extract it to `shared/` (or `core/`).
3. **YAGNI.** Build only what the task asks for. No "just in case" options, layers, interfaces or abstractions. No empty folders.
4. **No extra layers.** No generic base classes (`BaseComponent`, `BaseService`), factories, or patterns that do not solve a real problem today. Composition over inheritance.
5. **Material first.** If Angular Material or the CDK solves it, use it instead of building a custom component.
6. **One place per responsibility:**
   - Supabase queries → only in `*.repository.ts`, always through `unwrap()` / `unwrapNullable()`.
   - State → only in `*.store.ts`, with signals.
   - Stock and order rules → in Postgres (RPC + RLS + triggers), not in Angular.
   - Secrets (Telegram token, OpenRouter key, service role key) → only as Edge Function secrets. Never in Angular or in the repo.
7. **Small files.** ESLint stops at 250 lines per file, 60 per function, complexity 10. If you hit a limit, split by responsibility; do not disable the rule.
8. **Never disable checks** (`eslint-disable`, `@ts-ignore`, `any`) to make something pass.
9. **Minimal changes.** Touch only what the task requires; do not reformat or "improve" unrelated files.
10. If a task forces you to break one of these rules, **stop and ask**.
11. Do not use comments if possible instead prefer descriptive code and a good naming variables.
12. Do not use `any`.
13. If you will use comments make them simple. Use simple characters for comments do not use hyphens or semicolons.

## Architecture (summary)

- `core/` app singletons (Supabase, auth, layout) · `shared/` generic, no business logic · `features/` one folder per business feature.
- A feature never imports another feature (ESLint blocks it).
- Feature layout: `pages/` (smart, routed) · `ui/` (dumb, only `input()`/`output()`) · `data-access/` (repository + store) · `models/`.
- Styles only through `--cp-*` tokens or `--mat-sys-*`; never a hex value in a component. `.cp-cta` is only for the main buy button.
- **Mobile first.** Most customers arrive from WhatsApp on a phone. Design at 360px first, then scale up with `min-width` media queries. Check every page at 360px, 768px and 1280px with no horizontal overflow.
- SSR: no `window`/`document`/`localStorage` without `isPlatformBrowser` or `afterNextRender`.
- Auth: guests (anonymous) by default; Google OAuth is the only login for customers and admins, linking the anonymous identity on sign-in. No email or magic link.
- Hosting: handled by the owner, not decided yet. Wherever it runs, `NG_ALLOWED_HOSTS` must list the production domain.

## TypeScript

- Strict typing. No `any`; use `unknown` when the type is uncertain.
- Infer types when obvious.
- Use `interface` for object shapes.

## Angular (v22)

- Standalone components; do NOT write `standalone: true` (default).
- Do NOT write `changeDetection: OnPush` (default in v22). The app is zoneless.
- `input()`, `output()`, `model()`; never `@Input`/`@Output` decorators.
- `computed()` for derived state; `linkedSignal()` when it depends on several sources and must reset.
- `resource()` to load async data in stores.
- `inject()` instead of constructor injection.
- `@Service()` for new singleton services (instead of `@Injectable({ providedIn: 'root' })`).
- Signal Forms (`@angular/forms/signals`) for new forms.
- Native control flow (`@if`, `@for`, `@switch`); `track` is required in `@for`.
- `[class.x]` and `[style.x]` bindings; no `ngClass`/`ngStyle`/`CommonModule`.
- No `@HostBinding`/`@HostListener`; use `host: {}` in the decorator.
- Inline templates and styles by default; separate files only when the template exceeds ~40 lines.
- `NgOptimizedImage` for static images.
- Routes are always lazy (`loadComponent` / `loadChildren`).
- The root component selector (`cp-root`) must match the tag in `src/index.html`.
- Icons: Material Symbols loaded by name in `src/index.html` (`icon_names`). When using a new icon, add it there in alphabetical order.

## Accessibility

- Must pass AXE and WCAG AA: visible focus, contrast, ARIA, labels on form fields, `alt` on images.

## Tests

- Vitest. Test logic (stores, mappers, helpers, guards). No trivial "should create" tests except for `App`.

## Skills

Priority: this CLAUDE.md and docs/ always win over any skill.

- Database work (migrations, RLS, RPC, triggers): `supabase` + `supabase-postgres-best-practices`.
- Large features (schema, QR checkout, admin panel): Superpowers flow (brainstorm → write-plan → execute-plan). Small changes: skip it.
- Tests: follow the "Tests" section above (test logic, not trivial components), even if a skill asks for TDD on everything.
